## List export

Lists with an **Export CSV** button (FLOW-48: inventory, ingredients, bar, low stock, clients, venues, events, leads, staff, time reports and lead sources) build the file in the browser (`DataTable` `exportName`, `src/services/csv.ts`, ADR-09): every row that matches the current search and filters, in the table's current sort, not just the visible page. On paged lists (clients, venues, events, leads, inventory, ingredients and supplies, bar, low stock) the export first fetches every remaining page through the same list endpoint (`exportAll`, `usePagedList().loadAll`, FLOW-216), so each request stays inside the Worker's CPU budget; the button shows how many rows have arrived and can't be pressed again, and if any page fails nothing is downloaded and the error is shown. Columns are the table's columns (action and checkbox columns are left out); a column can give a plainer CSV value through `meta.csv`. A column that holds a field group (`meta.fieldGroup`, e.g. unit cost as `internal_cost`, client contact details, staff phone numbers) is left out of the file entirely for anyone who may not see that group, so Kitchen Staff exports have no client contacts and Staff exports no costs. Files are UTF-8 with a byte order mark, comma-separated with CRLF line endings, quoted per RFC 4180, and text that starts with `=`, `+`, `-` or `@` is prefixed with an apostrophe so spreadsheets don't run it as a formula. File names are `<list>-<New York date>.csv`.
