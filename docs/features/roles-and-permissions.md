## Roles and permissions

Settings › Roles & permissions (`/settings/permissions`, FLOW-269; `src/app/roles-permissions.tsx`, API `worker/routes/permissions.ts`, logic in `worker/records/permissions.ts`, model in `shared/role-permissions.ts`). Admin sets what each role may do in each **area** (Leads, Clients, Proposals, Events, BEOs, Production, Tasks, Staff directory, Staff pay, Inventory and Bar, Purchasing, Vendors, Recipes and Menus, Documents, Marketing photos, Reports, Settings and users, Live editing) as a colored pill: **None**, **Read** (every record, read-only), **Own** (read and write, only records assigned to them; Leads, Clients, Proposals, Events and BEOs) or **Write** (every record). A second grid sets which roles see each dashboard card and custom card.

- **Stored and seeded:** the `role_permissions` table holds a level per role and area. Rows are seeded on first load from the built-in rules in `shared/policy.ts`, so day-one behavior is unchanged: a cell left at its seeded level uses the built-in rule exactly (including finer rules such as who may count stock), and a changed cell replaces it. `can()` and the scope helpers (`clientScope`, `leadScope`, `eventScope`) read the matrix through hooks set by `setPolicyMatrix`; the Worker loads it per request (`worker/app.ts`, on wherever Hyperdrive is bound), the browser after sign-in and when data changes. A changed cell decides by its level: None denies the whole area, Read allows only the area's read actions, Own and Write allow all of them (Own limits records to the role's own).
- **Cache:** the Worker keeps the matrix in memory. A save drops this isolate's copy at once and caches the new one; other isolates re-read it after 5 seconds (`POLICY_TTL_MS`), so a change is live on the next request. If it can't be read the last copy, else the built-in rules, stand.
- **Admin is locked to Write** on every area (`matrixProblem`, 400 `INVALID_PERMISSIONS`), so no one can lock Admins out; its column is read-only in the editor. Staff pay (`staff.pay.read/write`) and Marketing photos (`marketing.read/write`) are areas with no screens yet: Admin-only until an Admin grants them.
- **Card visibility:** a dashboard or custom card has `visibleTo` roles on its block in the page layout (FLOW-253/256; the card's Style popover in layout edit mode, or the second grid, which saves the `dashboard.home` layout). A card shows only if the role is in `visibleTo` and can read the card's source area (`blockVisible` in `src/app/page-grid.tsx`).
- **Saving** (`PUT /api/permissions`, `users.manage`) is audit-logged as `role_permissions` with before and after for each changed cell. Everyone signed in reads the matrix (`GET /api/permissions`) because the browser evaluates the same policy.
